# «Сфера» — Информационная система заказов праздничных услуг и контроля качества

«Сфера» — это современная веб-платформа (маркетплейс) для автоматизации заказов праздничных услуг и контроля качества их выполнения. Система связывает клиентов, которым требуются услуги для проведения мероприятий, и исполнителей (провайдеров услуг), предоставляющих профессиональный сервис. Платформа поддерживает полный E2E-цикл взаимодействия: создание заявок, отправка предложений, оформление заказов, имитация оплаты, QR-подтверждение этапов работ, оценка качества и модерация.

---

## 1. Технологический стек

### Бэкенд (Backend)
* **Язык**: Python 3.10+
* **Фреймворк**: Django 4.2+ & Django REST Framework (DRF)
* **Аутентификация**: JWT (JSON Web Tokens) с HttpOnly-cookie для refresh токенов
* **База данных**: PostgreSQL (для продакшна) / SQLite (для быстрого локального демо)
* **Безопасность & Ограничения**: DRF Throttling (ограничение частоты запросов), кастомные валидаторы паролей и бюджетов, CORS/CSRF заголовки
* **Контейнеризация**: Docker & Docker Compose

### Фронтенд (Frontend)
* **Фреймворк**: Next.js 15+ (App Router)
* **Язык**: TypeScript
* **Локализация**: next-intl (поддержка трех языков: Русский, English, Қазақ)
* **Управление состоянием**: Zustand
* **Сетевой клиент**: Axios с централизованными хелперами эндпоинтов
* **Стилизация**: TailwindCSS (Premium UI с плавной анимацией и отзывчивой версткой)
* **Интерактивные карты**: Leaflet Map API для отображения координат услуг

### Интеграция с искусственным интеллектом (AI)
* **Функционал**: Опциональные бэкенд-помощники для автогенерации описания заявок и составления писем-предложений.
* **Спецификация**: Интеграция с LLM моделями (OpenRouter / OpenAI).
* **Надежность**: Поддержка гибридного режима — при отсутствии API-ключа бэкенд автоматически возвращает качественные локализованные шаблоны автогенерации (fallback mode), гарантируя бесперебойный запуск демо.

## 2. Пользовательские роли

1. **Гость (Guest)**: Просмотр каталога услуг, фильтрация по категориям и городам, просмотр публичных профилей исполнителей.
2. **Клиент (Client)**: Публикация заявок на мероприятия (с помощью AI-ассистента), выбор и утверждение предложений от исполнителей, оплата заказов, генерация QR-кодов для подтверждения этапов работ, написание отзывов и подача жалоб.
3. **Исполнитель (Provider)**: Создание и управление карточками услуг (в рамках лимитов подписки), отправка предложений клиентам (с помощью AI-ассистента), календарь занятости, сканирование QR-кодов клиента для активации/завершения заказа, управление портфолио, покупка тарифных планов.
4. **Модератор / Администратор (Staff/Admin)**: Просмотр жалоб, вынесение решений по модерации, блокировка и разблокировка учетных записей исполнителей, просмотр системных логов (AuditLog).

---

## 3. Ключевые возможности (Core Features)

* **Ролевой доступ (Role Guards)**: Строгое разграничение клиентских, исполнительских и администраторских разделов на уровне роутинга Next.js и бэкенд-пермиссий Django.
* **Интерактивный каталог**: Карта Leaflet, поиск, сортировка по цене/дате и фильтрация по категориям.
* **Жизненный цикл заказа**: Цепочка «Заявка → Предложение → Заказ → Оплата → QR-валидация → Отзыв».
* **QR-контроль выполнения**: Двухэтапная валидация начала и завершения работ через сканирование QR-токенов исполнителя.
* **AI-ассистенты**: Автоподбор текста заявок и сопроводительных писем.
* **Чат в реальном времени**: Обсуждение деталей заказа между клиентом и провайдером.
* **Система уведомлений**: Оповещения о новых предложениях, сменах статуса заказов и ответах на отзывы.
* **Модерация жалоб**: Панель администратора для обработки жалоб с фиксацией действий модератора в AuditLog.
* **Биллинг и промокоды**: Подписки на тарифные планы провайдеров с валидацией промокодов на скидки.

## 4. Локальный запуск (Local Setup)

### Вариант А. Запуск без Docker (Локальное окружение)

#### 1. Настройка Бэкенда (Django)
```bash
# Перейдите в директорию бэкенда
cd backend

# Создайте виртуальное окружение
python -m venv venv

# Активируйте виртуальное окружение
# Для Windows:
venv\Scripts\activate
# Для Linux/Mac:
source venv/bin/activate

# Установите зависимости
pip install -r requirements.txt

# Создайте локальный файл конфигурации из шаблона
copy .env.example .env

# Выполните миграции базы данных (будет создана db.sqlite3)
python manage.py migrate

# Запустите бэкенд сервер
python manage.py runserver
```
Бэкенд будет доступен по адресу: `http://127.0.0.1:8000/`.

#### 2. Настройка Фронтенда (Next.js)
```bash
# В новом терминале перейдите в директорию фронтенда
cd frontend

# Установите пакеты npm
npm install

# Создайте локальный файл конфигурации фронтенда
copy .env.example .env.local

# Запустите сервер разработки
npm run dev
```
Фронтенд будет доступен по адресу: `http://localhost:3000/`.

---

### Вариант Б. Запуск через Docker Compose (Полный стек)

1. Убедитесь, что у вас запущен Docker Desktop.
2. Скопируйте файл переменных окружения:
   ```bash
   cp backend/.env.example backend/.env
   ```
3. Запустите сборку и старт контейнеров:
   ```bash
   docker-compose up --build
   ```
4. Выполните миграции бэкенда внутри контейнера:
   ```bash
   docker-compose exec backend python manage.py migrate
   ```
5. Запустите фронтенд локально (перейдите в `frontend/`, выполните `npm install` и `npm run dev`).

## 5. Переменные окружения (.env)

> [!WARNING]
> Никогда не коммитьте файлы с секретами бэкенда `backend/.env` и фронтенда `frontend/.env.local` в Git репозиторий. Для хранения шаблонов настроек используются только `.env.example` файлы.

### Бэкенд (`backend/.env.example`)
* `DEBUG`: Режим отладки (1 для локального тестирования, 0 для продакшна).
* `SECRET_KEY`: Уникальный секретный ключ Django (в продакшене при `DEBUG=0` его указание обязательно, иначе сервер не запустится).
* `ALLOWED_HOSTS`: Список разрешенных хостов бэкенда.
* `CORS_ALLOWED_ORIGINS` / `CSRF_TRUSTED_ORIGINS`: Адреса фронтенда для безопасности кросс-доменных запросов.
* `DATABASE_URL`: Строка подключения к PostgreSQL (если не задана, Django использует SQLite `db.sqlite3`).
* `AI_API_KEY` (Опционально): Ключ API для интеграции с LLM.
* `AI_API_URL` (Опционально): URL эндпоинта completions API.

### Фронтенд (`frontend/.env.example`)
* `NEXT_PUBLIC_API_URL`: Полный адрес API бэкенда (по умолчанию для локального запуска: `http://127.0.0.1:8000/api/v1`).

## 7. Демонстрационный сценарий (Demo Flow)

Для проведения презентации и проверки функционала рекомендуется следующий сценарий:
1. **Регистрация Исполнителя**: Создайте аккаунт с ролью **Исполнитель** (например, `provider1@test.com` / `password123`).
2. **Создание услуги**: В кабинете исполнителя создайте услугу (например: «Ведущий на юбилеи»).
3. **Регистрация Клиента**: Создайте аккаунт с ролью **Клиент** (например, `client1@test.com` / `password123`).
4. **Создание заявки (AI Request Assistant)**: Перейдите в раздел «Создать заявку». Заполните поля города, бюджета и нажмите **«Улучшить с ИИ»** для автогенерации детального описания. Создайте заявку.
5. **Отправка предложения (AI Offer Assistant)**: Войдите под аккаунтом исполнителя, перейдите в «Заявки клиентов», найдите созданную заявку, выберите свою услугу, укажите цену и нажмите **«Составить с ИИ»** для генерации сопроводительного письма. Отправьте предложение.
6. **Принятие предложения**: Войдите под клиентом, откройте детальный просмотр заявки и нажмите **«Принять предложение»** на карточке исполнителя. Будет автоматически создан заказ в статусе ожидания оплаты.
7. **Оплата заказа**: Перейдите в «Мои заказы» под клиентом, нажмите «Оплатить» (происходит успешная имитация оплаты). Статус заказа меняется на «В работе», генерируются QR-коды активации и завершения.
8. **QR Старт**: Клиент показывает QR-код начала работ. Исполнитель сканирует его (или нажимает кнопку подтверждения), переводя заказ в фазу выполнения.
9. **QR Завершение**: По окончании работ клиент показывает QR-код завершения. Исполнитель сканирует его, подтверждая выполнение обязательств.
10. **Отзыв и Ответ**: Клиент оставляет оценку и текстовый отзыв. Исполнитель пишет ответ на отзыв.
11. **Жалоба и Модерация**: Клиент нажимает кнопку «Пожаловаться» на услугу исполнителя. Создайте суперпользователя через терминал (`python manage.py createsuperuser`), зайдите под ним в панель модератора `/ru/admin/reports/` и обработайте жалобу (проведите расследование, примите или отклоните, при необходимости заблокируйте провайдера).

## 10. Известные ограничения проекта (Known Limitations)

1. **Эквайринг**: Реальный платежный шлюз не подключен. В MVP используется безопасная имитация транзакции с валидацией балансов бэкендом.
2. **Карты**: Для отображения геолокации используется бесплатная Leaflet Map. Интеграция с 2GIS MapGL JS запланирована в качестве будущего улучшения (Stage 24.1).
3. **Хранение медиа**: Для загрузки изображений в портфолио и отзывов используется локальное файловое хранилище (Media Root). В промышленной эксплуатации Render рекомендуется подключить S3-совместимое облако (например, AWS S3 / Yandex Object Storage).
4. **Cookie сессий**: Настройка SameSite куки для кросс-доменных запросов на Render требует размещения фронтенда и бэкенда на поддоменах одного общего родительского домена для корректного прохождения куки авторизации в браузерах.
